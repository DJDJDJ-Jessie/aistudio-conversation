# 用 Codex 生成拆书任务包

拆书工坊支持导入一个以 `.bookflow.json` 结尾的本地任务包。一个任务包可以包含一个或多个组，每个组可以包含任意数量且有明确顺序的对话，每个对话下面可以包含任意数量且有明确顺序的轮次。导入成功后，工作台会立即显示完整计划，仍可逐项修改，确认后再开始串行执行。

## 最省事的使用方式

1. 把电子书文件、拆分规则、每轮要发送的固定要求，以及需要附带的图片交给 Codex。
2. 要求 Codex读取本项目的 `docs/bookflow-package.schema.json`，直接在本项目或你指定的目录生成一个 `.bookflow.json` 文件。
3. 打开拆书工坊，把文件拖到左侧“导入任务包”。在还没有组时，也可以拖到首页的“导入 Codex 任务包”。
4. 也可以点击同一个区域选择文件。扩展会一次创建全部组、对话、轮次、文字和图片。
5. 检查模型与系统指令，然后点击“开始串行执行”。

如果希望把书籍路径、输出目录、任务包格式规范、参考示例和 System instructions 等项目全部集中在提示词开头，直接使用 [Codex 生成拆书任务包提示词模板](../examples/Codex生成拆书任务包提示词模板.md)。模板还规定了导航窗格目录截图、5000—7000 字目标、章节不可截断、目录与正文完整覆盖、Codex 自主决定对话和轮次等规则。

也可以直接向 Codex提出这样的简化任务：

> 读取这本书，按照自然章节边界拆分正文，并自主安排独立对话和轮次。每轮 `text` 只能放对应的原书标题和原书正文，不得添加任务说明、书名包装、范围说明、上下文说明或 `【原文】` 标签；所有拆书要求统一放在组级 System instructions。请读取 `D:\CodeSpace\aistudio-conversation\docs\bookflow-package.schema.json` 和参考任务包，校验后将结果直接写成 `D:\你指定的目录\书名.bookflow.json`，不要把整份 JSON 粘贴到聊天回复里。

如果章节不是现成的，可以把规则说清楚，例如“按 Markdown 一级标题切分”“按目录中的章标题切分”“每轮不超过 5 万字，但不要从段落中间切开”。Codex 应先识别章节边界，再按你给出的每个对话轮次数量分配。对话边界会新开 AI Studio 页面；同一对话里的轮次会延续上下文。

## 任务包结构

最小结构如下：

```json
{
  "format": "aistudio-bookflow",
  "version": 1,
  "groups": [
    {
      "name": "书名 · 全书拆解",
      "model": "gemini-2.5-pro",
      "system": "这里填写 System instructions",
      "timeoutMinutes": 30,
      "focusIntervalSeconds": 10,
      "exportMode": "headings",
      "conversations": [
        {
          "title": "对话 A",
          "turns": [
            {"title": "第 1 章", "text": "第 1 章标题和完整原文"},
            {"title": "第 2 章", "text": "第 2 章标题和完整原文"}
          ]
        }
      ]
    }
  ]
}
```

完整约束见 [bookflow-package.schema.json](bookflow-package.schema.json)，可直接导入的 3 / 3 / 4 示例见 [拆书任务包示例.bookflow.json](../examples/拆书任务包示例.bookflow.json)。

组级 `model` 和 `system` 是默认设置。某个对话可以填写自己的 `model` 或 `system` 来覆盖组设置。`system` 可以直接写成字符串，也可以使用以下对象：

`focusIntervalSeconds` 控制执行期间 AI Studio 执行窗口切到桌面最前面的频率，单位为秒，可设为 2–120，省略时默认 10。置顶会转移当前键盘焦点。

- `{"mode":"custom","text":"……"}`：自定义系统指令。
- `{"mode":"preset","preset":"网页中的预设名称"}`：选择 AI Studio 中已有的系统指令预设。
- `{"mode":"none"}`：明确关闭系统指令。

轮次的 `text` 会原样进入工作台正文框并发送给 Gemini，因此只应包含源书中本轮对应的原书标题和原书正文。任务要求、输出格式和分析规则放在组级 `system`；处理范围放在对话标题和轮次标题；目录层级通过图片附件表达。不要在 `text` 中增加 `【任务】`、`【书籍】`、`【本轮范围】`、`【上下文说明】` 或 `【原文】`。

图片必须嵌入任务包，不能只填写本机路径。每项图片使用 `name`、`type` 和 `base64`，也可以使用完整的 `dataUrl`。支持 PNG、JPEG、WebP 和 GIF；单张最多 20 MB，每轮图片合计最多 60 MB。纯文字书不需要 `attachments`。

## 导入时的处理

扩展先在内存中校验整个文件，校验通过后才开始保存。导入途中发生存储错误时，本次已经写入的组和图片会被撤销。任务包中的 ID、运行状态和历史结果不会被导入；所有组、对话、轮次和图片都会获得新的本地 ID，并从“尚未执行”状态开始。

一个包最多包含 30 个组；每组最多 30 个对话、合计 300 轮；每个对话最多 100 轮；单轮文字最多 500 万字符；任务包文件最多 200 MB。导入成功后内容自动保存在扩展本地数据库中，因此任务包可以移走或删除。保留任务包则便于以后重新导入或在另一台电脑上建立同一套计划。
