# Codex 生成拆书任务包提示词模板

复制下面的完整提示词，只修改开头的“用户填写区”。标有“留空则自动”的项目可以不填。

````text
请根据下面的用户填写信息，读取书籍、识别完整目录、截取目录图片、拆分正文，并生成一个可以直接导入“拆书工坊”的 `.bookflow.json` 任务包。

==================== 用户填写区 ====================

【书籍文件路径】（必填）


【任务包输出目录】（必填）


【任务包格式规范路径】（可留空；默认使用 D:\CodeSpace\aistudio-conversation\docs\bookflow-package.schema.json）


【任务包参考示例路径】（可留空；默认使用 D:\CodeSpace\aistudio-conversation\examples\拆书任务包示例.bookflow.json）


【System instructions 模式】（可留空；默认选择“网页已有预设”。也可以填写“自定义指令”或“不使用系统指令”）


【网页已有预设名称】（可留空；默认“经济类拆书”。只有 System instructions 模式为“网页已有预设”时使用）


【自定义 System instructions 完整内容】（可留空；只有 System instructions 模式为“自定义指令”时才填写）


【处理范围】（可留空；默认处理全书正文，包括有实质内容的前言、引言、结语和后记，排除版权页、重复目录、页眉页脚、页码和广告）


【组名称】（可留空；默认使用“识别到的书名 · 全书拆解”）


【Gemini 模型】（可留空；默认使用 gemini-2.5-pro）


【每轮原文字数目标】（可留空；默认 5000—7000 个中文字符）


【每个独立对话的轮数】（可留空；默认由你根据上下文长度和内容连续性自主决定，一般为 2—4 轮）


【每轮异常等待上限】（可留空；默认 30 分钟）


【导出方式】（可留空；默认 headings）


【目录导航窗格所在的软件及打开方法】（可留空；请先自行识别当前书籍格式和可用阅读软件。若我已说明，请写在这里）


【目录校正方式】（可留空；默认“自动核对，并在临时工作副本中修复目录结构；不得修改或覆盖原书”）


【目录截图要求】（可留空；默认“必须生成并附加”。只有我明确填写“无需截图”时才允许省略）


【其他特殊要求】（可留空）


================== 用户填写区结束 ==================

从这里开始全部是执行规则。不要要求用户在后文继续寻找或替换字段。凡是用户填写区留空的项目，直接采用该项目写明的默认值，并根据书籍实际情况自行作出合理决定。

System instructions 必须按以下规则写入组级 `system`：

1. 用户未填写“System instructions 模式”时，默认生成 `{"mode":"preset","preset":"经济类拆书"}`；
2. 用户选择“网页已有预设”但没有填写预设名称时，仍使用 `经济类拆书`；
3. 用户选择“网页已有预设”并填写了名称时，生成 `{"mode":"preset","preset":"用户填写的准确名称"}`；
4. 用户选择“自定义指令”时，生成 `{"mode":"custom","text":"用户填写的自定义 System instructions 完整内容"}`；自定义内容为空时必须在生成任务包前报告缺失，不能擅自改用其他文字；
5. 用户选择“不使用系统指令”时，生成 `{"mode":"none"}`；
6. 默认情况下不得把 System instructions 写成普通字符串，不得生成空的自定义指令，也不得把预设名称写进 `text`；
7. `经济类拆书` 是 AI Studio 网页已有预设的准确名称。任务包只保存预设名称，扩展会在每个新对话开始时选择该网页预设。

一、总体任务

请充分发挥判断能力，直接完成以下工作：

1. 打开并读取完整书籍；
2. 完整读取书籍自带的印刷目录、目录页或出版方目录，即使这些目录使用普通正文样式、表格、文本框或图片，而不是 Heading 样式；
3. 分别建立“书内目录树”和“正文真实标题树”，再将二者合并为“最终合并目录树”：正文中真实存在的标题一个都不能删除，书内目录中提供的完整编号、缺失项目和可靠层级也必须补入；
4. 将最终合并目录树与现有导航窗格逐项对账，检查缺项、多项、缺少“第一章”等编号、重复、顺序错误或层级错误；
5. 目录有误时，在临时工作副本或纯目录视图中恢复最终合并目录树；原始书籍保持不变；
6. 打开校正后工作副本的导航窗格或校正后目录视图并逐项复核；
7. 按大章节截取校正后的完整目录截图；
8. 根据正文结构和字数目标自主拆分轮次；
9. 根据内容连续性自主安排独立对话和每个对话的轮次；
10. 完成 Word 校准后，以校准完成的 Word 为唯一正文来源，将每轮对应的校准后正文和目录截图写入任务包，所有拆书要求只放在组级 System instructions；
11. 校验原文覆盖情况和任务包格式；
12. 将最终文件直接保存到用户填写的输出目录。

不要让用户提前指定总轮数或固定的 3/3/4 编排。不要只生成空结构、计划、示例或占位符。任务包里的每一个轮次都必须包含该轮实际书籍原文，不能混入任务说明或人为添加的包装文字。

除非文件无法访问、文件损坏、需要解密密码，或者缺少完成任务不可替代的输入，否则不要停下来询问。普通的章节边界、对话数量、轮次安排和文件命名由你按照这些规则自行决定。

二、目录核对、校正与导航窗格截图

目录截图指书籍阅读软件或文档软件中的导航窗格、文档结构窗格或目录树截图。截图的目的，是让 Gemini 在处理正文时能够看到当前内容在整本书和所属大章中的层级位置。

现有导航窗格不一定正确，不能把它直接当成唯一依据。最终截图目录既不能只复制书籍自带目录，也不能只复制正文现有标题样式；它必须是“正文真实标题树”和“书内目录树”的合集。正文负责提供实际存在的全部真实标题、正文顺序和内容边界；书内目录负责补充“第一章”等完整编号、正文或原导航遗漏的目录项目，并帮助判断父子层级；现有导航窗格只用于发现需要修复的问题。必须先完成两棵树的合并、核对和必要校正，再截图。

### 2.1 目录核对依据

按以下规则分别建立目录树并合并：

1. 先从头到尾完整读取当前书籍自带的印刷目录、目录页、目录章节或出版方目录，不得只读取 Word 的 Heading 样式、PDF 书签或现有导航窗格；
2. 书内目录即使是普通正文样式、表格、文本框、扫描图片或跨多页内容，也必须完整提取；图片目录需要 OCR 后逐项复核，不得因为提取困难而省略目录项；
3. 对每个书内目录项记录完整目录路径、完整编号、完整标题、父级、同级顺序和对应页码或定位信息，形成“书内目录树”；页码、点线和作者署名等版式信息不作为标题文字，除非它确实属于书中标题；
4. 再从头到尾检查正文，识别正文中实际承担结构作用的篇名、章名、小章、小节和其他标题，记录标题原文、正文位置、父级和出现顺序，形成“正文真实标题树”；不得只读取现有 Heading 样式，必须结合排版、编号、上下文和内容边界识别漏设样式的真实标题；
5. 页眉、页脚、正文首句、图注、人物问答、案例名称和普通加粗段落不能仅凭样式被当作正文标题；但一旦确认某段确实是正文结构标题，即使书内印刷目录没有列出，也必须进入最终合并目录树，不能删除或忽略；
6. 将两棵树按同一章节的语义身份合并。书内目录与正文指向同一个节点时只保留一个节点；如果书内目录比正文多出“第一章”等编号，使用书内目录的完整编号加标题作为目录标签。例如书内目录是“第一章 用生命周期看待长期价值”，正文标题只有“用生命周期看待长期价值”，最终合并目录必须显示完整的“第一章 用生命周期看待长期价值”；
7. 书内目录有、正文标题树没有的项目必须补入最终合并目录树；正文标题树有、书内目录没有的真实标题也必须补入最终合并目录树。最终合并目录是两者的并集，不能以任何一个来源覆盖另一个来源；
8. 最终目录的实际章节顺序优先服从正文中的出现顺序。只在正文找不到对应项目时，才按照书内目录中相邻项目的位置插入；父子层级综合正文包含关系、编号规律和书内目录层级判断；
9. 如果两个标题只是“有无章号、空格或明确的版式符号”不同，可以自动合并并使用书内目录的完整标签。如果实质标题文字不同且无法确认是同一节点，不能静默删除任何一方；保留两个真实节点并在最终报告中说明冲突，或在确实无法确定父级时暂停；
10. 阅读软件的导航窗格、文档结构树、PDF 书签或 EPUB 导航只代表现有元数据，必须与最终合并目录树对账；
11. 不得自行创造两个来源都不存在的章号或标题。最终目录中每个节点都必须能追溯到书内目录、正文真实标题，或二者合并后的完整标签；原始书籍绝不能为了目录校正而改变。任务包 `text` 在第二阶段从校准完成的 Word 提取，因此必须保留校准后标题中的完整编号。

至少检查以下问题：

- 正文中有真实标题，但导航窗格缺失；
- 正文中有真实标题，但书内印刷目录没有列出；
- 书内目录存在某一篇、章或节，但正文标题样式和导航窗格都没有收录；
- 书内目录标题包含“第一章”“第二章”等编号，而正文标题或导航项目只有章名；
- 普通正文、页眉页脚、图注或重复目录被误收为导航标题；
- 大章、小章、小节的层级设置错误；
- 同一个标题在导航中重复；
- 一个标题因换行或排版被错误拆成多个目录项；
- 导航项目缺号、跳号、乱序，或与正文出现顺序不一致；
- 导航标题与正文可见标题不一致；
- 目录节点没有展开，导致子章节在截图中被隐藏。

遇到多个来源互相矛盾时，正文中的实际标题覆盖和正文顺序不能被书内目录删除或改写；书内目录中的独有项目也不能因为正文标题样式缺失而被丢弃。若书内目录是“第一章 完整章名”，正文只写“完整章名”，这是可以自动确认的同一节点，最终合并目录和校准后 Word 标题都使用书内目录的完整标签。第二阶段生成任务包时直接保留该校准后标题。只有当两者的实质标题或章节归属冲突、且无法通过内容边界可靠判断时，才暂停并说明具体歧义；不得凭空编造目录项或拆解正文。

### 2.2 在临时工作副本中校正

1. 任何目录修复都必须在临时工作副本或独立的校正后目录视图中完成。原始书籍文件只读，绝不能修改、覆盖、另存回原路径或改变原书内容；
2. 工作副本保存到用户填写的任务包输出目录或系统临时目录，文件名应能明确识别，例如 `书名-目录校正工作副本.docx` 或 `书名-纯目录视图.docx`；文件名可以用于本地管理，但不得把“目录校正视图”“纯目录视图”等字样写进截图画面；
3. 工作副本用于完成 Word 目录与标题校准，并在校准完成后成为第二阶段生成任务包的正文来源；独立纯目录视图只能用于截图，不能作为任务包正文来源；
4. 对 Word、DOCX 或其他以标题样式生成导航的文档，先按照最终合并目录树调整标题样式和大纲级别，移除误加在普通正文上的标题样式，并为正文中漏设样式的真实标题补上正确层级；
5. 如果正文标题缺少书内目录已有的章号或上级编号，应在工作副本中把该标题校正为书内目录的完整标签。例如工作副本中的“用生命周期看待长期价值”应校正为“第一章 用生命周期看待长期价值”。原书保持不变；第二阶段生成任务包时，`text` 必须使用工作副本中的完整校准后标题，不能再去掉“第一章”；
6. 如果最终合并目录树中的项目在原导航中完全缺失，无论它来自书内目录还是正文真实标题，都必须在工作副本的导航结构或独立纯目录视图中补入，并放在正确父级和顺序位置；不能因为找不到现成 Heading 段落就省略；
7. 对 PDF、EPUB 或其他使用书签、Outline、TOC 元数据的格式，如果工具允许，应在工作副本中按照最终合并目录树补充、删除、调整层级或重新排序书签元数据；书页可见正文保持不变；
8. 如果当前格式无法安全生成完整导航窗格，就根据最终合并目录树建立一份独立纯目录视图并截图；
9. 纯目录视图和最终截图的画面只能包含目录节点文字以及表达层级所必需的缩进、展开箭头或树线。不得出现书名页标题、页面标题、“目录”“校正后目录视图”“按书内目录逐项核对”等说明、正文段落、缺失说明、来源说明、处理备注、页码、目录点线、作者署名、页眉、页脚、日期、边框装饰或其他非目录内容；
10. 如果使用文档软件生成纯目录视图，裁剪截图时也必须排除软件工具栏、页面空白之外的说明区和其他界面，只保留清晰、紧凑的目录树区域；
11. 完成校正后，分别核对书内目录树和正文真实标题树。两个来源中的每个有效节点都应在最终合并目录中恰好出现一次；合并后的完整编号不能丢失，正文独有标题不能删除，父子层级和正文顺序必须正确；
12. 建立“最终合并目录路径 → 节点来源（书内目录/正文/二者）→ 最终目录标签 → 原导航状态 → 校正动作 → 正文范围 → 所属大章截图 → 对应轮次”的内部映射；
13. 对于书内目录存在、但正文中确实找不到对应标题或内容的项目，最终合并目录仍要保留该目录项，并只在任务完成报告中列出“目录已补充、正文未找到对应内容”；这句话绝不能出现在目录视图或截图里。不得为它虚构正文，也不得创建空轮次；
14. 不得把目录校正过程中的说明文字、来源备注或人为包装写入任务包的 `text`。任务包正文段落来自校准后的工作副本；已经核实并写入工作副本的完整标题属于校准后正文，必须保留。

示例：

```text
书内目录：第一章 用生命周期看待长期价值
正文标题：用生命周期看待长期价值
原导航：用生命周期看待长期价值（错误地与所有小节同为第一层）

校正后截图目录：
第一章 用生命周期看待长期价值
    生命周期与均值回归
    偏向价值的 GARP 策略
    站在新时代的起点
    投资理念与观点（正文真实标题，书内目录未列，仍然必须保留）

任务包 text：从校准后 Word 标题“第一章 用生命周期看待长期价值”开始，必须保留“第一章”。
```

上面的括号仅用于解释本模板规则。制作真实目录视图和截图时，只能显示该节点在正文中的原始标题 `投资理念与观点`，不得显示括号中的来源说明。

### 2.3 截取校正后的完整目录

1. 先完成书内目录树、正文真实标题树、最终合并目录树的建立和必要校正，再开始切分正文和截图；
2. 以最终合并目录树识别“部/篇 → 大章 → 小章 → 小节”等真实层级；
3. 从校正后工作副本的导航窗格或独立纯目录视图，为每个需要处理的大章节制作一套完整目录截图；
4. 一套大章节目录截图必须从该大章标题开始，覆盖该大章下面的全部小章和小节，一直到下一个同级大章出现之前；
5. 不得只截取当前轮正文包含的两个或三个小节；
6. 如果当前轮只发送某个大章的第一节和第二节，而该大章还有第三节、第四节，那么截图仍必须显示这个大章下面的第一节至最后一节；
7. 如果整个大章的目录无法放进一张截图，使用多张连续截图完整覆盖；相邻截图保留适量重叠，确保中间没有目录项遗漏；
8. 截图必须清晰到能够辨认标题、层级、编号和展开关系；
9. 截图前展开当前大章的完整目录树，不要让未展开节点隐藏后续小节；
10. 同一大章被拆到多个轮次时，将这套完整的大章节目录截图附加到该大章对应的每一个轮次；
11. 如果一轮跨越两个大章节，附加这两个大章节各自的完整目录截图；
12. 不要把全书目录压缩成一张无法辨认的小图；按大章分别截图；
13. 将目录截图以 PNG、JPEG 或 WebP 保存，并以 Base64 或 Data URL 嵌入对应轮次的 `attachments`；
14. 图片文件名应能看出所属大章、已经过校正以及图片顺序，例如 `第三章-校正后完整目录-01.png`、`第三章-校正后完整目录-02.png`；如果核对后无需修复，也可以沿用 `第三章-完整目录-01.png`；
15. 在写入任务包前逐张检查图片可读取、格式受支持、内容完整且对应正确大章；将所有截图合起来分别与书内目录树和正文真实标题树逐项核对，确认两者有效节点覆盖率都为 100%，所有“第一章”等编号均完整保留，书内目录或正文已有而原导航缺失的项目均已补充；
16. 对截图做画面内容检查：除目录节点与必要的层级符号外，任何“目录校正视图”、说明、正文、页码、作者、备注、页眉页脚或装饰文字的数量都必须为 0。

如果用户没有明确填写“无需截图”，目录截图就是最终任务包的必需内容。如果当前环境确实无法操作书籍软件的导航窗格或无法截图，不要伪造截图，也不要把缺少截图的任务包报告为已经完成。可以先完成可验证的目录识别和文字拆分草案，然后明确说明阻塞原因以及用户需要补充的截图或操作；取得真实截图后再生成最终任务包。

三、章节识别与正文清理

优先根据正式标题、目录编号、导航层级和排版识别章节，不要只凭字数猜测边界。

正文处理要求：

1. 保持原书顺序；
2. 保留所有有实质内容且属于用户处理范围的正文；
3. 排除版权信息、出版信息、重复目录、页眉页脚、页码、广告和明显扫描噪声；
4. 不把目录文字重复当作正文；
5. 不改写正文；
6. 不用摘要代替原文；
7. 不为了控制文件大小删除正文段落；
8. 不重复粘贴相同正文；
9. 不遗漏跨页或跨文件衔接的段落；
10. 对 OCR 错误保持谨慎，只有能够明确判断时才修正；
11. 不能确定某段是否属于正文时，优先保留，并在最终报告中说明。

四、每轮 5000—7000 字的拆分原则

字数目标只计算该轮实际书籍原文，不计算任务说明、范围说明和固定提示词。

章节完整性的优先级高于凑字数。按以下规则自主组合：

1. 从书籍开头开始，严格按照原书顺序处理；
2. 将小章、小节或其他最小完整标题单元作为优先拆分边界；
3. 加入下一个完整单元前，先计算加入后的原文字数；
4. 加入后仍不超过约 7000 字时，继续加入；
5. 加入后会明显超过 7000 字时，在当前完整单元结束处结束本轮，把下一个完整单元从头放到下一轮；
6. 绝不能为了达到 5000 字或不超过 7000 字，从一个小章、小节或语义完整单元的中间截断；
7. 因为保持完整边界而不足 5000 字时，允许该轮低于 5000 字；
8. 单个不可继续细分的完整单元本身超过 7000 字时，保留整个单元，允许该轮超过 7000 字；
9. 一个长的大章存在清晰小节时，可以在小节边界拆成多轮；
10. 一个长的大章没有可靠的下一级标题时，不要随意从正文中间截断；将其作为完整轮次，并在最终报告中说明超长原因；
11. 不得为了让各轮字数看起来平均而破坏章节结构。

例如，一个大章有三个小节，字数分别为 2800、3000、2600：

- 第一轮放第一节和第二节，约 5800 字；
- 第二轮完整放第三节，约 2600 字；
- 两轮都附加能够显示该大章全部三个小节的完整导航窗格目录截图。

第二轮不足 5000 字是合理结果，不能把第三节截断，也不能为了补字数随意混入不相干章节。

五、大章节完整覆盖原则

同一个大章可以被分到多个轮次，但相关轮次合起来必须从头到尾覆盖该大章。必须满足：

1. 每个需要处理的大章、小章和小节都恰好收录一次；
2. 不遗漏当前轮因字数限制未加入的后续小节；
3. 下一轮从下一个完整小节的开头继续；
4. 不在相邻轮次之间重复正文；
5. 不颠倒顺序；
6. 每个轮次的标题标明所属大章和小节范围；
7. 一个大章分成多轮时，标题标明“第 1 部分 / 共 3 部分”等信息；
8. 每个相关轮次都附加该大章的完整目录截图，而非只显示本轮小节的局部截图。

六、对话编排原则

请根据拆分后的实际轮次数量和内容关系，自主决定对话数量和每个对话的轮次数量。

1. 同一对话中的轮次会延续 Gemini 上下文；
2. 下一个对话是完全独立的新上下文；
3. 内容连续、属于同一主题或同一大章的相邻轮次优先安排在同一对话；
4. 一个对话一般安排 2—4 轮，但可根据用户填写值和实际内容调整；
5. 不要让一个对话累计过长上下文；
6. 很长的大章可以独占一个对话；
7. 每个新对话都会重新应用组级 System instructions，再发送该轮纯原文和完整目录截图；对话标题与轮次标题只用于工作台中的本地识别，不要把它们转写成正文包装；
8. 每个对话使用明确名称，例如“对话 A · 前言与第一章”“对话 B · 第二章”；
9. 对话顺序和轮次顺序必须与原书顺序完全一致；
10. 存在多个合理方案时，选择最有利于内容连续、上下文清晰和稳定执行的方案，无需询问用户。

七、每轮实际发送内容

从本节开始进入第二阶段：生成任务包。第二阶段必须以第一阶段已经校准完成的 Word 工作副本为唯一正文来源，并相信第一阶段已经完成目录、标题文字、编号和层级校准。不要重新把输入当成未经校准的普通文档，不要再次独立建立目录树或推翻校准结果，也不要回到原始书籍提取任务包正文。

如果第二阶段发现校准后的 Word 仍有明显缺号、缺标题或层级问题，应返回第一阶段修正工作副本并重新确认，然后再从修正后的 Word 继续生成任务包；不得只在 JSON 中临时猜测、补写或删除标题。

每个轮次的 `text` 只能包含该轮在校准后 Word 中对应的实际书籍内容。扩展会把 `text` 原样放进轮次正文框并发送给 Gemini，因此不得添加任何任务包装、解释、元数据或上下文提示。

本模板所说的“纯原文”在生成任务包阶段，专指“校准后 Word 中的可见正文内容”：包括校准后 Word 已经补全的章标题、小节标题和编号，以及标题下面保持原文不变的正文段落。标题校准不等于任务包装；例如校准后 Word 中的标题是“第一章 用生命周期看待长期价值”，`text` 就必须原样包含“第一章 用生命周期看待长期价值”，不能为了追求校准前的字面原样而删除“第一章”。

`text` 中禁止出现 Codex 人为添加的以下内容：

1. `【任务】`；
2. “请按照 System instructions……”；
3. `【书籍】` 和人为重复添加的书名；
4. `【本轮范围】`；
5. “这是第 X 部分，共 Y 部分”；
6. `【上下文说明】`；
7. “请延续上一轮……”；
8. `【原文】`；
9. 字数说明、拆分理由、对话编号和轮次编号；
10. “待填写”“请替换这里”“TODO”等占位文字。

这些信息应分别放在正确位置：

- System instructions：默认由组级网页已有预设 `经济类拆书` 提供；只有用户选择“自定义指令”时，才把用户填写的完整要求放入组级 `system.text`；
- 书名和整本书任务名称：放在组的 `name`；
- 对话处理范围：放在 conversation 的 `title`；
- 大章、小节范围以及“第几部分”：放在 turn 的 `title`；
- 大章节在全书中的目录层级：通过该轮的目录截图 `attachments` 表达；
- 轮次正文框：只放 turn 的 `text`，而 `text` 只允许是校准后 Word 中的实际书籍内容。

校准后 Word 中已有的章标题、小节标题和完整编号属于正文，必须保留。这里禁止的是 Codex 额外添加的包装标签，绝不允许借此删除“第一章”等校准后标题文字。

每个 `text` 应从校准后 Word 中本轮第一个完整正文单元的第一个字符开始，到本轮最后一个完整正文单元的最后一个字符结束。不要在开头增加说明，也不要在结尾增加说明。不要把上一轮内容重复放入下一轮。

组级 System instructions 会在每个新对话开始时重新设置，因此不需要在轮次正文中重复任务要求。默认 `system` 必须是 `{"mode":"preset","preset":"经济类拆书"}`；如果用户明确选择自定义模式，自定义 `text` 才需要写成适用于每个独立对话、每个轮次的完整规则。

正确示例：

```json
{
  "title": "第一章 · 用生命周期看待长期价值 · 第 1 部分 / 共 1 部分",
  "text": "第一章 用生命周期看待长期价值\n\n生命周期与均值回归\n\n……校准后 Word 中本轮最后一个自然段。"
}
```

上例只演示 `title` 与纯原文 `text` 的边界。生成正式任务包时，仍须按照本模板的目录截图规则，把实际取得的完整目录截图编码后写入同一轮的 `attachments`；不得复制任何示意图片数据或占位值。

错误示例是把 `【任务】`、`【书籍】`、`【本轮范围】`、`【上下文说明】` 或 `【原文】` 放入 `text`。即使这些说明看起来有帮助，也一律不要添加。

八、任务包设置和格式

开始设计任务包结构前，必须先读取用户填写区指定的“任务包格式规范路径”和“任务包参考示例路径”。如果用户留空，分别使用字段中写明的默认路径。

格式规范决定允许使用的字段、层级、数据类型和限制；参考示例用于理解一个真实任务包怎样组织组、对话和轮次。格式规范的优先级高于参考示例。如果示例与格式规范不一致，以格式规范为准。

不要直接修改参考示例文件。请根据当前书籍创建一个新的任务包，并保存到用户填写的“任务包输出目录”。

任务包必须满足：

1. `format` 为 `aistudio-bookflow`；
2. `version` 为 `1`；
3. 默认一个组承载整本书；
4. 组名、模型、System instructions、等待上限和导出方式使用用户填写区的值或其默认值；System instructions 留空时必须写为 `{"mode":"preset","preset":"经济类拆书"}`；
5. 根据实际分析结果创建所需的 `conversations` 和 `turns`；
6. 每轮写入实际 `title`、从校准后 Word 提取的正文 `text` 和对应目录截图 `attachments`；
7. 不写入 `run`、`result`、已完成状态或外部 ID；
8. 不生成空轮次；
9. 不遗漏正文；
10. 不伪造无法取得的目录截图；
11. 生成文件名时使用识别出的书名，并以 `.bookflow.json` 结尾；
12. 将文件直接写入用户填写的输出目录，不要把完整 JSON 粘贴到聊天回复里。

如果格式规范文件或参考示例文件无法读取，先在项目路径中查找同名文件。仍然找不到格式规范时，不要凭记忆猜测任务包结构，也不要生成可能无法导入的文件；请明确报告缺少的文件路径。参考示例缺失但格式规范可以读取时，可以严格依据格式规范继续生成。

九、生成前后的完整性检查

写文件前直接沿用第一阶段已经核实的“最终合并目录路径 → 节点来源（书内目录/正文/二者）→ 最终目录标签 → 原目录问题 → 校正后层级 → 校准后正文范围 → 对话 → 轮次 → 纯目录截图”内部映射，不在第二阶段重新建立另一套目录判断，然后检查：

1. 是否已经从头到尾完整读取书籍自带目录，包括普通正文样式、表格、文本框或图片中的目录；
2. 是否已经建立包含完整编号、完整标题、顺序和父子层级的书内目录树；
3. 是否已经从头到尾检查正文并建立正文真实标题树，包括书内目录没有列出的真实标题；
4. 是否已经将两棵树合并为最终合并目录树，而不是用书内目录覆盖正文标题；
5. 原导航中的缺失、误入、缺编号、重复、乱序和层级错误是否全部识别；
6. 书内目录树和正文真实标题树中的每个有效节点是否都在最终合并目录及截图中恰好出现一次，两者覆盖率是否都达到 100%；
7. 正文中存在而书内目录未列出的真实标题是否全部保留；
8. 书内目录中的“第一章”“第二章”等编号是否完整进入最终目录，没有因为正文标题缺编号而丢失；
9. 书内目录或正文已有而原导航缺失的项目是否全部补充，并位于正确父级和正文顺序位置；
10. 纯目录视图和截图是否只包含目录节点及必要层级符号，所有页面标题、说明、正文、页码、作者、备注、页眉页脚和装饰文字是否为 0；
11. 如需校正，是否只修改了截图专用工作副本或独立纯目录视图，并确认原始书籍文件保持不变；
12. 任务包正文是否始终从第一阶段校准完成的 Word 工作副本提取，并完整保留“第一章”等校准后标题编号；
13. 所有需要处理且正文中实际存在的大章和小节是否都有对应轮次；
14. 每段正文是否恰好出现一次；
15. 是否有遗漏、重复或顺序颠倒；
16. 每轮原文字数是否已计算；
17. 每个拆分点是否位于完整章节或小节边界；
18. 被拆成多轮的大章是否已经完整覆盖；
19. 每轮是否附加所属大章的校正后完整目录截图；
20. 多张目录截图之间是否连续且没有漏项；
21. 新对话第一轮是否能依靠组级 System instructions、校准后正文和完整目录截图独立执行；
22. 每个 `text` 是否只含校准后 Word 中的实际书籍内容，没有任何人为包装标签或任务说明；
23. 每个 `text` 的首尾是否准确落在校准后 Word 的完整正文单元边界；
24. JSON 是否能正常解析并符合任务包规范；
25. 所有图片是否能解码且满足支持格式和大小限制；
26. 最终文件是否与参考示例采用相同的根结构、组、对话和轮次层级；
27. 生成文件是否存在、非空，并能由任务包解析器成功读取。

发现问题时自行重新拆分、补齐截图或修正任务包，直至检查通过。

十、完成报告

完成后不要粘贴完整 JSON，只报告：

1. 任务包的完整路径；
2. 识别出的书名；
3. 大章和小节数量；
4. 最终轮次数量；
5. 独立对话数量以及每个对话的轮数；
6. 每轮原文字数；
7. 哪些轮次因保持章节完整而低于或超过目标范围；
8. 每个大章生成了几张完整目录截图；
9. 是否确认所有要求截图的轮次都已附加完整目录截图；
10. 是否确认校准后 Word 的所有正文完整覆盖、没有重复、没有遗漏；
11. 是否确认所有轮次的正文框都只有校准后 Word 中的实际书籍内容，没有任务包装，并保留了“第一章”等完整标题编号；
12. 任务包格式校验是否通过；
13. 原目录是否存在问题；如果存在，列出修复了哪些缺项、误项、重复项、顺序或层级问题；
14. 目录校正工作副本的完整路径，并确认原始书籍文件未被修改；
15. 截图来自原本正确的导航窗格、已经校正的工作副本还是独立纯目录视图；
16. 书内目录节点总数、正文真实标题节点总数、合并后的节点总数，以及两个来源各自的截图覆盖率；两个覆盖率都必须为 100%；
17. 哪些标题补回了书内目录中的“第一章”等完整编号；
18. 哪些书内目录项目原导航缺失、现已补充；
19. 哪些正文真实标题未列入书内目录、现已补充；
20. 哪些书内目录项目在正文中没有找到对应标题或内容；
21. 是否确认所有目录截图中只存在目录节点和必要层级符号，没有标题、说明、正文、页码、作者或备注；
22. 文件是否可以直接导入拆书工坊。

现在直接开始执行。
````
