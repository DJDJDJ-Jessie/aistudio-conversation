# 拆书工坊 · AI Studio 串行助手

根据 `1.zip`、`2.zip`、`3.zip` 和 `3.1.zip` 中的 AI Studio DOM 实现的本地浏览器扩展。使用 Google AI Studio 网页完成操作，不调用 Gemini API，也不需要配置 API Key。需要在安装扩展的同一个浏览器中登录 AI Studio。

## 项目与文件的关系

整个项目只有一个根目录：`D:\CodeSpace\aistudio-conversation`。各文件的关系如下：

```text
D:\CodeSpace\
├─ 1.zip / 2.zip / 3.zip / 3.1.zip    DOM 输入包，只作为分析资料
└─ aistudio-conversation\             本程序唯一的项目根目录
   ├─ manifest.json                   从整个项目根目录加载插件的入口
   ├─ extension\                      浏览器插件正式源码，由根目录入口引用
   ├─ artifacts\                      历史打包输出；本机加载和运行都不读取
   ├─ docs\                           DOM 分析、验证结果与界面截图
   ├─ tests\                          自动测试源码和本地模拟网页
   ├─ test-results\                   自动测试的临时工作目录，不属于插件运行数据
   ├─ scripts\                        打包脚本
   ├─ README.md                        当前使用说明
   ├─ package.json / package-lock.json 开发与测试依赖清单
   └─ node_modules\                   本项目本地开发依赖；插件运行不使用它
```

`extension` 是正式插件代码，项目根目录的 `manifest.json` 是浏览器入口。浏览器只需要加载 `D:\CodeSpace\aistudio-conversation`；运行时不会读取 `artifacts`，也不存在另一套本地程序。

运行插件时不读取 `D:\CodeSpace\1.zip`、`2.zip`、`3.zip` 或 `3.1.zip`。以后 AI Studio 改版需要重新核对 DOM 时，才会再次读取这些上级目录文件。本项目不再长期保存解压后的 DOM 副本。

## 安装

适用于支持 Manifest V3 的 Chrome / Edge，最低 Chromium 120。扩展无需编译。

1. Chrome 地址栏输入 `chrome://extensions`，或在 Edge 输入 `edge://extensions`。
2. 打开“开发者模式”，点击“加载已解压的扩展程序”。
3. 直接选择整个项目根目录：`D:\CodeSpace\aistudio-conversation`。根目录已经包含可供浏览器识别的 `manifest.json`，不需要再解压任何文件。
4. 点击扩展图标“拆书工坊”，进入完整工作台。
5. 在同一个浏览器中登录 [Google AI Studio](https://aistudio.google.com/app/prompts/new_chat)。

需要复制到另一台电脑时，可以复制整个项目目录，再加载其中的 `manifest.json`。插件无需运行本地服务，无需安装 Node.js 或 Python。`artifacts` 中若仍有旧 ZIP，它只是历史打包产物，可能不包含当前修改，不应作为本机安装入口。

工作台使用浏览器中的完整扩展页面，而不是窄侧栏。拆书任务要同时容纳多个对话、长章节文字、图片、轮次顺序、模型设置和结果预览，完整页面更适合编辑和核对。这个页面仍属于同一个浏览器扩展，不是独立桌面程序，也不会创建另一份项目或运行数据。

## 用 Codex 一次生成完整拆书计划

如果逐章复制粘贴仍然费时，可以让 Codex 读取电子书并直接生成一个 `.bookflow.json` 任务包。任务包可以一次包含多个组；每个组可以自定义模型、System instructions、等待上限和导出方式，并包含任意数量、按顺序排列的对话与轮次。每轮可以带完整文字和以 Base64 嵌入的图片。

生成后，可以把任务包直接拖到工作台左侧的“导入任务包”，也可以点击该区域选择文件；还没有组时，首页的“导入 Codex 任务包”也同时支持拖入。扩展会先校验整个文件，再一次创建所有组、对话、轮次和图片。导入内容自动保存到扩展的本地数据库，任务包里的外部 ID、执行进度和历史结果会被忽略，导入后的任务从尚未执行状态开始。

任务包中的 `turn.text` 会原样进入轮次正文框，因此它只应包含对应的原书标题和原书正文。拆书要求和输出格式统一写入组级 System instructions；对话标题与轮次标题用于本地编排；大章节目录通过图片附件提供。生成任务包时不要在正文中添加 `【任务】`、`【书籍】`、`【本轮范围】`、`【上下文说明】` 或 `【原文】`。

详细提示词和使用方法见 [Codex 生成拆书任务包](docs/Codex生成拆书任务包.md)。可以直接复制 [提示词模板](examples/Codex生成拆书任务包提示词模板.md)，只填写模板最上方的书籍路径、输出目录和拆书要求；任务包格式规范与参考示例已有默认路径，也可以在那里改成其他位置。模板会要求 Codex 自主识别章节，按 5000—7000 字目标且不截断小节进行拆分，并把所属大章的完整导航窗格目录截图嵌入相关轮次。完整机器可读格式见 [任务包 JSON Schema](docs/bookflow-package.schema.json)，也可以先试导入 [3 / 3 / 4 示例任务包](examples/拆书任务包示例.bookflow.json)。

## 按 10 章、3 / 3 / 4 执行

1. 新建一个组，填写书名或本次任务名称，例如“周期 · 全书拆解”。
2. 将“要新开几个对话”设为 `3`，再分别把对话 A、B、C 设为 `3`、`3`、`4` 轮。会生成 3 个有明确顺序的独立对话，共 10 轮。
3. 在各轮填入章节原文、拆解要求和图片。可以从剪贴板粘贴截图，也可以选择或拖入图片。
4. 如已有每章一个 `.txt` / `.md` 文件，点击“导入章节文件”。文件按名称自然排序，优先填入现有空轮次，超过空轮次数量的内容追加到最后一个对话。
5. 在右侧“执行设置”中设置模型、System instructions 和 AI Studio 置顶间隔。置顶默认每 10 秒执行一次，可设为 2–120 秒。可以自定义指令、选择网页已有预设，或明确不使用系统指令；对话右上角的设置按钮可以覆盖模型和指令。
6. 可点击“读取网页选项”，在独立检测页读取当前账号网页中能看到的模型和预设。这个操作不会发送消息。
7. 点击“开始串行执行”。右侧会自动切到独立的“运行与结果”页，同时创建一个专用 AI Studio 执行窗口。只有当前轮次正式回复完整结束、结果成功写入本地后，才会发下一轮。
8. 全部完成后点击“下载完整 Markdown”。文件进入浏览器的默认下载目录，文件名就是组名称，例如 `周期 · 全书拆解.md`。工作台里的“打开浏览器下载目录”可以直接打开所在文件夹；如果浏览器启用了“下载前询问保存位置”，则会先弹出保存窗口。

模型输入框既可以选择列表中的 ID，也可以输入完整模型 ID。初始列表来自提供的 DOM，实际可用模型以当前账号的网页为准。

## 执行与保存

- 一个组表示一次完整拆书任务。程序为当前组创建一个固定在桌面右边缘的专用 AI Studio 大窗口，宽度约为当前屏幕的 68%，并保证常见桌面上至少约 1050 像素，避免 AI Studio 因窄窗口隐藏模型和 Run settings 控件。每个对话使用全新的页面，并在该对话即将执行时才创建。新对话建立并接管执行后，上一对话页面自动关闭；整组完成并保存最后一轮后，执行窗口自动关闭。
- 一个对话中的所有轮次沿用上下文；切换到下一个对话时重新设置模型和系统指令。
- 每轮发送前都会确认关闭 `Code execution`、`Grounding with Google Search` 和 `URL context`。切换模型后也会重新检查；无法确认关闭时暂停，不发送该轮。
- 每轮可包含文字、图片，或仅图片。支持 PNG/JPEG/WebP/GIF，单张最多 20 MB，每轮图片总计最多 60 MB。这是扩展的传输限制，AI Studio 仍可能有自己的限制。上传时会分别显示“识别图片预览”“等待上传进度结束”“图片上传已确认”和“等待 Run 可用”，便于判断实际卡在哪一步。
- 组、章节文字、图片和正式回复保存在扩展的本地 IndexedDB 中。每轮完成都会保存，不需要等整本书结束。
- 工作台通过扩展内部事件实时更新当前对话、当前轮次、执行阶段、已完成数量和进度条。右侧“执行设置”与“运行与结果”分开展示；运行页再将实时进度、任务操作、保存与导出、完成判断和执行记录分成独立区域。关闭工作台不会停止任务；重新打开后会读取最新状态。
- 自动保存负责保存任务计划和逐轮回复；最终 `.md` 文件不会自动写入项目目录。全部完成并收到通知后，点击“下载完整 Markdown”才会生成用户文件。
- 工作台只是编辑和查看窗口。AI Studio 当前对话会保持为专用执行窗口里的活动页面。为了适配只有在桌面可见时才持续渲染结果的情况，执行窗口会按组设置的间隔切到最前面并重新贴到工作台所在屏幕的右边缘，默认每 10 秒一次；这个动作会转移键盘焦点。请不要手动修改当前执行页。运行期间扩展还会请求系统保持唤醒，并禁止浏览器自动丢弃执行页面。
- 每个对话的 AI Studio 页面地址都会保存在该组的“运行与结果 → 已记录的 AI Studio 对话页面”中。上一对话页面或整个执行窗口关闭后，可以逐个重新打开；关闭工作台、刷新页面或下次打开浏览器后，记录仍在。只有 AI Studio 已把 `new_chat` 变成独立会话地址时才能恢复原网页；如果网站始终停留在 `new_chat`，程序会明确提示无法重建，但已保存的 Markdown 不受影响。
- 扩展不会按固定时间猜测回复完成。它会确认本轮的新 Gemini 回复、正式回复操作区、Run 按钮空闲状态以及正文稳定状态，并排除思考过程后才保存和发送下一轮。
- 默认“异常等待上限”为 20 分钟，可改成 1–120 分钟。它只在网页卡住、网络中断或登录失效等异常情况下暂停；不会跳过该轮，也不会盲目重发。
- “本轮完成后暂停”会等待正在生成的回复完整保存，再暂停。它不会强行截断 Gemini 正在生成的内容。
- 暂停、异常、浏览器重启后，已完成结果保留；能验证原执行页面时，可以继续后续轮次或恢复当前回复采集。
- 任一轮发生异常时，整个组会停在该轮，不会自动跳过并继续后续轮次。工作台显示红色原因，扩展图标显示 `!`，浏览器弹出“拆书任务已暂停，需要检查”通知；修复页面问题后点击“检查后继续”。
- 运行过的组锁定编排。需要改文字、模型、轮次或顺序时，使用“复制为新组”，避免更改发送中的计划。
- 任意时刻都能下载已完成的部分，文件名仍然是组名称。文件进入浏览器的默认下载目录；如果浏览器启用了“下载前询问保存位置”，则由你选择文件夹。文件自身是当前结果的快照，下载后不会被扩展继续改写。
- Codex 任务包只负责批量建立执行计划，不是结果备份。导入成功后可以删除任务包；若保留它，以后可以重新建立一套全新的同内容计划。

默认导出仅拼接正式回复，不添加标题，以免破坏拆书要求中的纯多级列表。汇总文档页面还可选择“添加对话与轮次标题”。回复从网页渲染结构转换为 Markdown，保留语义结构，但不是 AI Studio 后端原始 Markdown 字符串的逐字节拷贝。

## 异常后怎么处理

| 状态 | 处理方式 |
| --- | --- |
| 模型不存在 / 无权限 / Run 不可用 | 打开执行页面检查模型、登录或额度；修正后点击“检查后继续”。如要更换执行计划，请复制为新组。 |
| 上传无法确认 | 错误中会显示识别到的预览数、文件控件接收数和上传进度状态。在执行页面确认附件；若页面文字与图片数和本轮完全一致，继续时会沿用已有附件，否则先清空残留内容。仍无法识别时，导出当前上传完成状态的 DOM 供适配。 |
| 已记录发送意图，但网页刷新或断网 | 恢复时只采集已有回复，不再次点击 Run。先在原执行页面确认该轮是否已有正式回复。 |
| 页面已经完成但采集超时 | 检查正文和反馈按钮是否完整出现，展开折叠的代码块；然后“检查后继续”。 |
| 当前独立对话的第 1 轮尚未记录发送意图，执行标签页已关闭或 ID 失效 | 点击“检查后继续”；程序新建 AI Studio 页面，从模型和系统指令设置阶段重新准备。本轮此前没有点击 Run，因此不会重复发送。 |
| 已记录发送意图后执行标签页关闭 | 点击“执行页面”或“检查后继续”。如果 AI Studio 已生成独立会话地址，程序会重新打开并接管，只检查和采集已有回复，不再次点击 Run；没有独立地址时会停在当前轮次并说明原因。 |
| 同一对话后续轮次在发送前丢失原页面 | 先从“已记录的 AI Studio 对话页面”尝试打开；无法恢复完整上下文时，不会在空白页盲目续接。下载已有结果，复制为新组后安排未完成内容。 |
| 浏览器重新启动 | 页面记录和已保存结果仍在。独立会话地址可重新打开；当前轮次只有在发送记录与会话地址都足以核对时才会继续，无法确认时仍会暂停。 |

发送意图落盘和网页 Run 点击无法形成跨系统原子事务。扩展选择保守策略：在“可能已发送”的情况下停止重发，这避免自动重复提交，但意味着极少数情况下需要人工检查，并可能需要在新组中重做该轮。

清除扩展数据、卸载扩展或更换浏览器配置文件会影响工作台中的本地计划。最终交付文件统一使用 Markdown，不再提供容易与结果文件混淆的 `backup.json` 入口。

## 已有验证和仍需联调的部分

- 已用 `1.zip` 的 6 份原始 DOM、`2.zip` 的工具设置页、`3.zip` 的新版模型与系统指令页，以及 `3.1.zip` 的图片上传完成、生成中和回复完成页检查控件定位。模型入口兼容旧版 `model-selector-card` 与新版 `model-selector-trigger`；图片完成按 `ms-prompt-media`、token 状态、移除按钮和 Run 状态核对。`3.1.zip` 还显示 AI Studio 会把下一轮的空白输入位渲染为 `User` 节点，并会在生成过程中卸载长用户正文；扩展现按已提交消息的结构标记、节点 ID 和顺序识别真实轮次，不再把空白输入位误判为人工新消息。
- 正式回复提取测试逐段核对页面 06 的正文，检查嵌套列表、思考过程排除、代码块和表格转换。
- 独立浏览器集成测试使用实际安装的扩展、实际 IndexedDB、图片 FileList 注入和模拟 AI Studio 网页。它不向真实 Gemini 发送测试内容。
- **尚未在你的已登录 AI Studio 页面上完成整组端到端验证。** `3.1.zip` 已覆盖图片上传完成、生成中与最终完成，但仍没有图片正在上传、配额错误和刷新恢复时的完整 DOM。站点对真实多轮连续操作的处理仍需要实际任务联调。
- 如果站点改版导致确认条件不成立，扩展会暂停，不会假定完成或抓取整页内容。

详细 DOM 证据和架构见 [DOM-分析与实现](docs/DOM-分析与实现.md)，具体测试场景见 [验证结果](docs/验证结果.md)。

## 开发

```text
npm install
npm test
npx playwright install chromium
npm run test:browser
npm run package
```

如果本机 Playwright 附带浏览器不能启动，可设置 `BOOKFLOW_TEST_BROWSER` 指向本机 Chrome 可执行文件，再运行浏览器测试。测试通过 Chrome 官方的 `Extensions.loadUnpacked` 调试接口在全新的测试配置文件里加载扩展，不接触用户日常浏览器配置。

需要重新运行原始 DOM 测试时，从上级目录的 `D:\CodeSpace\1.zip` 临时提取到 `reference-dom/pages`；检查结束后删除提取内容。原始包可能包含账号显示信息和书中文字，不会打入交付安装包。

所有运行代码和 Markdown 转换库都随扩展本地打包，没有远程 JavaScript、遥测、服务器或 API 密钥。转换库为 Turndown / turndown-plugin-gfm，许可证见 `extension/vendor`。
